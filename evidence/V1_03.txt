CASE ID: V1_03
CATEGORY: ACL
TITLE: ACL Blocking Traffic Between PC0 and Server0

==================================================

==================================================

Command:

Output:
Pinging 192.168.20.10 with 32 bytes of data:

Reply from 192.168.10.1: Destination host unreachable.
Reply from 192.168.10.1: Destination host unreachable.
Reply from 192.168.10.1: Destination host unreachable.
Reply from 192.168.10.1: Destination host unreachable.

Ping statistics for 192.168.20.10:
Packets: Sent = 4, Received = 0, Lost = 4 (100% loss)

Observation:
PC0 cannot reach Server0 at 192.168.20.10.


Command:
ping 192.168.10.1

Output:
Pinging 192.168.10.1 with 32 bytes of data:

Reply from 192.168.10.1: bytes=32 time<1ms TTL=255

Reply from 192.168.10.1: bytes=32 time<1ms TTL=255

Ping statistics for 192.168.10.1:
Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)

Observation:
PC0 can successfully reach its default gateway at 192.168.10.1.


==================================================
EVIDENCE 2: ROUTING TABLE
==================================================

Device: Router0

Command:
show ip route

Relevant Output:

C 192.168.10.0/24 is directly connected, GigabitEthernet0/0
L 192.168.10.1/32 is directly connected, GigabitEthernet0/0

Observation:
Router0 has directly connected routes to both the

==================================================
EVIDENCE 3: ROUTER INTERFACE STATUS
==================================================

Device: Router0

Command:
show ip interface brief

Output:

Interface              IP-Address      Status    Protocol
GigabitEthernet0/0     192.168.10.1    up        up
GigabitEthernet0/1     192.168.20.1    up        up

Observation:
Both router interfaces required for communication
between the two networks are operational.


==================================================
EVIDENCE 4: ACCESS CONTROL LIST
==================================================

Device: Router0

Command:
show access-lists

Output:

Extended IP access list 101

10 deny icmp host 192.168.10.10 host 192.168.20.10 (4 match(es))
20 permit ip any any (4 match(es))

Observation:
ACL 101 explicitly denies ICMP traffic from PC0
(192.168.10.10) to Server0 (192.168.20.10).

The deny rule has 4 matches, corresponding to the
four failed ping attempts.


==================================================
DIAGNOSTIC SUMMARY
==================================================

Symptom:
PC0 cannot ping Server0, but it can successfully
reach its default gateway.

Initial Analysis:
Router interfaces are up/up and both networks have
directly connected routes.

Additional Evidence:
ACL 101 contains a rule denying ICMP traffic from
PC0 to Server0.

CONFIRMED FAULT:
ACL 101 is blocking ICMP traffic from
192.168.10.10 to 192.168.20.10.

OSI LAYER:
Layer 3

RECOMMENDED FIX:
Remove or modify the incorrect deny rule in ACL 101
to permit the intended traffic
